## 1. Borrow a profile and visit its real spans

[`crates/qx-geometry/src/profile_plot.rs`, lines 148–160](../crates/qx-geometry/src/profile_plot.rs#L148-L160):

```rust
fn profile_spans(profile: &NurbsProfile, range: [f64; 2]) -> Vec<Span> {
    let p = profile.degree;
    let constant = profile.values.iter().all(|v| *v == profile.values[0]);
    (p..profile.values.len())
        .filter_map(|k| {
            let a = profile.knots[k].max(range[0]);
            let b = profile.knots[k + 1].min(range[1]);
            if b <= a {
                return None;
            }
```

`&NurbsProfile` is a shared borrow: this function can read the owner's authored
profile but cannot edit it. Unlike copying a C++ object with `auto profile`, this
does not copy its vectors. `range: [f64; 2]` is a small fixed array passed by value.
`p..len` visits valid span indices; it does not create a fixed sampling lattice.

The iterator's `filter_map` combines filtering with construction. A repeated knot
or clipped-out interval returns `None`, so it contributes no span. A real interval
returns `Some(Span { ... })` farther down, and `collect()` builds an owned vector
of temporary plotting data. `iter()` borrows each value; the closure's `*v` reads
the scalar behind that reference. Rust's iterator traits let these operations
compose while retaining concrete types checked by the compiler.

A comparable C++ starting point is:

```cpp
std::vector<Span> profile_spans(const NurbsProfile& profile,
                              std::array<double, 2> range) {
    std::vector<Span> result;
    for (std::size_t k = profile.degree; k < profile.values.size(); ++k) {
        const double a = std::max(profile.knots[k], range[0]);
        const double b = std::min(profile.knots[k + 1], range[1]);
        if (b <= a) continue;
        // Construct the temporary span net, then append it.
    }
    return result;
}
```

For QUANTUM Dynamics, this is the critical change in where drawing begins: every
nonzero knot interval is examined, including the tiny interval around 0.5003.
The following local arrays/blends compute a plotting basis without inserting
knots into the authored profile.

## 2. Bound a rational curve's error over the whole interval

[`crates/qx-geometry/src/profile_plot.rs`, lines 72–94](../crates/qx-geometry/src/profile_plot.rs#L72-L94):

```rust
        for j in 0..=p + 1 {
            let t = j as f64 / (p + 1) as f64;
            let left = self.h[j.min(p)];
            let right = self.h[j.saturating_sub(1)];
            let residual = (1. - t) * (left[0] - a * left[1]) + t * (right[0] - b * right[1]);
            let weight = (1. - t) * left[1] + t * right[1];
            error = error.max((residual / weight).abs());
        }
```

`self` is borrowed by `&self` in the method signature. The two-element homogeneous
coefficient arrays contain `f64`, which is `Copy`; assigning `left` and `right`
copies two numbers, not an allocation. `j.saturating_sub(1)` avoids unsigned
underflow at zero. `0..=p+1` includes its upper endpoint; `as f64` makes the numeric
conversion explicit.

The math matters more than the loop syntax. For `y=N/W` and chord `L`, the error
is `(N-LW)/W`. Positive denominator coefficients let the code bound the entire
error function from its Bernstein coefficients. A midpoint can happen to lie on
the chord even when two sizeable lobes lie between the endpoints. This method
still detects those lobes. It also respects rational weights: the graph's X is
the input parameter, not a weighted control-point X coordinate.

The corresponding C++ arithmetic would also use `double` and
`std::max(error, std::abs(residual / weight))`. Rust contributes explicit,
checked ownership around the same mathematics; it does not make the calculation
more accurate merely by being Rust. The roundoff and budget limits are documented.

## 3. Move temporary spans into results and propagate real errors

[`crates/qx-geometry/src/profile_plot.rs`, lines 311–335](../crates/qx-geometry/src/profile_plot.rs#L311-L335):

```rust
    let segments = refine(spans, tolerance, max_segments, false)
        .into_iter()
        .map(|(s, resolved)| {
            let x = s.x.map(|u| u * t.length);
            let from = [x[0], t.evaluate_validated(x[0])?.value];
            let to = [x[1], t.evaluate_validated(x[1])?.value];
```

The same expression finishes with:

```rust
        .collect::<Result<_>>()?;
```

`refine` owns its `Vec<Span>`. It moves spans between a pending stack and output
leaves, splitting only when the leaf budget allows it. Here `into_iter()` consumes
that temporary output vector and transfers each span into the closure. By
contrast, `.iter()` would lend references to those spans. Nothing consumes `t`:
it remains an immutable borrow of the original transition.

The endpoints are read through the existing evaluator. Each `?` means “if this
is an error, return that error from the closure immediately; otherwise unwrap
the successful value.” The closure therefore returns `Result<Segment>`.
`collect::<Result<_>>()` uses Rust's `FromIterator` implementation for `Result`:
it builds the vector if every item succeeds, or stops at the first error. `_`
asks the compiler to infer the inner vector type. The final `?` propagates that
error to the caller. It does not panic or silently remove a bad point.

In C++, an equivalent loop would append each successful segment and immediately
return a failed `std::expected<Plot, GeometryError>` when endpoint evaluation
fails. `std::move` would express ownership transfers. Rust makes the same
distinction part of the types and iterator interfaces.

For the application, the result owns only derived drawing data; document
ownership never moves into rendering. Errors reach the existing graph feedback.

## 4. Convert screen tolerance at the UI boundary

[`apps/quantum-x/src/authoring/graph_curve.rs`, lines 12–27](../apps/quantum-x/src/authoring/graph_curve.rs#L12-L27):

```rust
    let range = [mapping.x.min, mapping.x.max].map(|x| (x - offset).clamp(0., transition.length));
    // Half a logical pixel vertically. Knot spans remain mandatory even when
    // their horizontal width is smaller than a pixel in the current view.
    profile_plot::sample(
        transition,
        range,
        mapping.y.span() * 0.5 / mapping.rect.height() as f64,
        budget.clamp(1, 2048),
    )
```

The function borrows `&Transition` and `&Plot`. It clips global view coordinates
into the transition's local domain, then converts half a logical screen pixel
into output units. `array.map(...)` returns another fixed-size array. The final
function call has no semicolon: it is the function's returned expression.

The geometry crate receives numbers and a segment budget, with no egui types.
The painter later borrows `&mut usize` to reduce a shared frame detail allowance;
that exclusive mutable borrow affects a local drawing budget, not authored data.
Both draft and committed appearance use this same function. Dashing is a later
presentation step, so it cannot remove input intervals from sampling.

A C++ equivalent would accept `const Transition&` and `const Plot&`, calculate a
`double tolerance`, and pass those values to a UI-independent sampler. The Rust
signature makes shared access and returned errors explicit.

## 5. Fit the view without editing the curve

[`apps/quantum-x/src/authoring/graph_view.rs`, lines 60–82](../apps/quantum-x/src/authoring/graph_view.rs#L60-L82):

```rust
    pub fn fit(channel: &Channel) -> Option<Self> {
        channel.validate().ok()?;
        let (mut min, mut max) = (f64::INFINITY, f64::NEG_INFINITY);
        for t in &channel.transitions {
            let bounds = qx_geometry::profile_plot::bounds(t).ok()?;
            min = min.min(bounds[0]);
            max = max.max(bounds[1]);
        }
```

`Self` means `View` inside this implementation. `Option<Self>` is either
`Some(view)` or `None`; it cannot contain a null/dangling `View`. `.ok()` converts
a `Result` into an `Option`, matching the existing Fit operation's contract.
Here `?` returns `None` if the channel or bounds are invalid. The caller only
replaces the visible view when it receives `Some(view)`, preserving the current
view after failure. This continues the existing behavior; sampling errors in
painting have their separate explanatory readout.

`for t in &channel.transitions` borrows the vector and each transition. There is
no `&mut Channel`, so fitting cannot reshape profiles or create a document
command. The remainder retains the established constant-scale and 15% margin
rules. A C++ analogue is `std::optional<View> fit(const Channel&)` with early
`std::nullopt` returns and conservative bounds accumulation.

The practical result is that Fit Curve now includes the narrow extremum while
leaving the owner's authored curve, selection and undo history intact.
