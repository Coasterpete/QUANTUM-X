# M1.3 practical Rust/C++ guide

These five locations form the path from station assignments to the existing GPU
mesh. Excerpts are from the actual implementation, abbreviated only for focus.

## 1. Data ownership — `qx-style/src/construction_segments.rs`

```rust
pub struct ConstructionSegment {
    pub id: String,
    pub start_m: f64,
    pub end_m: f64,
    pub style_id: String,
    pub variant_id: String,
}
```

Each segment owns its ID strings, like C++ `std::string`; station values are
double precision SI metres. `ConstructionMap` owns `Vec<ConstructionSegment>`,
similar to `std::vector`. Serde derives explicit JSON conversion; it does not
make this part of the native project format. `deny_unknown_fields` rejects typos
instead of silently ignoring them. Spine count is encoded by structural sweeps,
not the count of running-rail sweeps.

numbers identical and preserve the exact reported final station.

## 2. Validated borrows and lookup — same module

```rust
pub struct ResolvedSegment<'a> {
    pub assignment: &'a ConstructionSegment,
    pub variant: &'a ConstructionVariant,
}
```

The references borrow existing data rather than clone all definitions. `'a`
means both references remain valid for the validated map's lifetime. C++ could
use `const` pointers/references or spans but relies on the caller to prevent
dangling pointers and mutation. Rust checks that the owner cannot destroy or
mutate these borrowed objects while the validated result is used. Private
validated-map fields prevent callers from skipping coverage checks.

```rust
let i = self.segments
    .partition_point(|s| s.assignment.start_m <= station_m)
    .saturating_sub(1);
```

This is C++ `std::upper_bound` followed by a guarded decrement. It selects the
right-hand interval at a boundary. Validation already proved exact coverage;
lookup first rejects stations outside the track. `saturating_sub` cannot wrap
zero to a huge unsigned value. Sorting uses `f64::total_cmp`, then rejects
nonfinite station values before accepting the map.

## 3. Segment mesh adapter — `qx-geometry/src/construction/segmented.rs`

```rust
let a = track.samples.partition_point(|s| s.distance_m <= start_m);
let b = track.samples.partition_point(|s| s.distance_m < end_m);
samples.push(at(start_m)?);
samples.extend_from_slice(&track.samples[a..b]);
samples.push(at(end_m)?);
```

Binary search finds the original samples strictly inside the interval. The
derived vector owns endpoint samples and copies the interior slice. `&track`
is immutable, so construction cannot change authored Regions, positions,
frames, design speed or force profiles through this API. Exact existing samples
bypass interpolation; new structural endpoints use the established track query.
Rails are built separately once from the full original sample slice, so they
do not acquire seams when structures change.

C++ could express the input as `const GeneratedTrack&` plus `std::span<const
Sample>`, with a local vector for cuts. Rust slices include bounds; invalid
indexing cannot silently read unrelated memory. The two partition predicates
ensure neither endpoint is duplicated in the interior slice.

## 4. Shared mesh generation — `qx-geometry/src/construction.rs`

```rust
let components = build_components(
    track, &track.samples, definition, Part::All, None,
    assets, &mut budget, &mut vec![],
)?;
```

Both the ordinary builder and segmented adapter call this existing engine.
`Part` is an enum, handled exhaustively by `match`, like a C++ enum class with
a checked switch. `&mut budget` lends exclusive mutable access to one aggregate
resource counter; segments cannot each quietly receive a fresh budget. The
`&dyn ConstructionAssets` argument is a borrowed trait object, comparable to a
C++ abstract interface reference. The renderer implements GLB resolution; the
numerical geometry crate never imports GPU types.

Repeaters retain the global `start + k * spacing` phase. A nearby rigid part
whose transformed vertices cross a structural cut is omitted with a bounded
diagnostic. Its source mesh is never modified to fit. Shared rails retain the
baseline's normals, winding, UVs and caps because their sweep call is unchanged.

## 5. Compatibility errors and sidecar adapter

`qx-style/src/construction_segments.rs` compares adjacent running definitions:

```rust
a.continuous.iter().filter(|c| c.role == Role::Running)
    .eq(b.continuous.iter().filter(|c| c.role == Role::Running))
```

These iterators borrow the sweeps and compare every value without allocating a
temporary list. A mismatch returns `Err(CatalogError(...))` containing the
boundary station and both segment IDs. `Result<T,E>` is analogous to C++23
`std::expected<T,E>`. The `?` operator propagates an error; it does not ignore it
or substitute another construction.

`apps/quantum-x/src/diagnostic_import/construction_map.rs` connects the pieces:

```rust
let map = ConstructionMap::from_json(&text)?;
let variants = box_spined_diagnostic_variants(base)?;
let valid = map.validate(track.length_m(), &variants)?;
```

The map and registered definitions live long enough for validation and mesh
generation in the same scope. Only the completed owned mesh/report escapes.
The existing reload worker replaces the visible scene after success; an error
leaves its previous mesh intact. This is independent of native project saving.
