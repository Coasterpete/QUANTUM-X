# M1.2 diagnostic import — compatibility investigation

## Read-only inspection before implementation

The local BROBDINGNAGIAN exports are private compatibility references. They are
never modified, packaged, or committed. Source hashes recorded on 2026-11-03:

- CSV SHA-256: `e352a17501b4e6b64c21278305e267e31670cd546d6e8291edc06f700f13981c`
- XML SHA-256: `70328e918d55589fc36be56992c78daddb8b46ad6672406c8f74a2773a3d2385`

The official [file format reference](https://nolimitscoaster.com/nolimits2/help/pages/fileformats.html#csvspline)
defines tab-separated rows, a one-based ordinal, position, and front/left/up
vectors. The local CSV has exactly those 13 columns, quoted headers, decimal
points, and 5,655 samples. The measured polyline length is 2,826.988199760 m;
XYZ bounds are (-348.345737, 32.537616, -418.322008) to
(-67.101648, 178.679788, 172.595532). The endpoint gap is 6.017345 m.
There is no topology flag: the supplied polyline remains open, without a closing
segment. This does not establish the topology of the original NL2 park.

The [Professional tab reference](https://nolimitscoaster.com/nolimits2/help/pages/professionaltab.html)
states that CSV export covers the longest track, whereas support export covers
the coaster. It does not export the entire multi-track park, terrain, vehicle
dynamics, native curve controls, Regions, materials, or exact rail meshes.

World XYZ is retained unchanged. NL2 uses metres and Y elevation (also corroborated
by its [telemetry coordinates](https://nolimitscoaster.com/nolimits2/help/pages/telemetry.html)).
The local front/up/left basis obeys `front × up = -left`. QUANTUM's local
T/N/L basis is therefore front/up/minus-left. This changes basis labels only;
it does not rotate, translate, mirror, or scale positions. Rounded vectors require
bounded normalization into QUANTUM's quaternion representation. The CSV reference
is documented only as the exported spline; an exact rail-center/heartline offset
is not specified in the file. Do not apply an assumed reference offset.

## XML inventory and ambiguities

The actual hierarchy is `root/supports`, containing 179 `rasc` rail connectors
with 179 positioned `subnode`s, 399 positioned `freenode`s, 290 positioned
`footernode`s, and 914 `beam`s. Beams contain 1,607 `beamnode`s, whose IDs are
subsequently referenced by other beams. Total node IDs: 2,475. IDs are arbitrary
text in the official format, even though this fixture uses decimal integers.
Every beam has `start`, `end`, `type="1"`, and `size1` (0.41148–0.9144).
Nested beam nodes use fractional `pos` and types 0/1 (ordinary node/flange).
No prefab element is present in this export: do not invent prefab transforms.

All connectors have type 2. 174 reference `custom_track_index=0`; five reference
index 1, absent from the track CSV. `center_rails_coord` is retained as an NL2
station reference, not treated as an exact match to sampled chord distance.
Connector subnodes supply authoritative world positions. Their shape/orientation
and track-specific attachment offsets are not encoded as complete solids.

Footer properties are `contype=0`, `basetype=1`, world `pos`, `rotation`, and
`height_above_terrain` (0.01524–0.3048 m). No explicit foundation dimensions or
terrain elevations are supplied. Preserve those properties and mark their world
positions; do not synthesize foundations or derive ground from these values.

Other properties: 152 `colormode_mainspine` markers, 297 rotations (290 footer,
seven beam), 11 `vertical` beam rotation modes, eight `end_extra_length` and
22 `start_extra_length` values, including negative trims. There are no explicit
node offset tags in this fixture. The
[support panel reference](https://nolimitscoaster.com/nolimits2/help/pages/supportspanel.html)
explains pipe outer diameter, rotation modes, extensions, footers, and flange
semantics, but does not publish numeric XML type mappings or foundation sizes.
Unsupported shapes and properties must be reported rather than silently filled.

Initial comparison at the XML station against CSV chord distance gives index-0
connector-to-spline distances 0.170211–1.081122 m (mean 0.815549 m), predominantly
in minus-up. These are attachment offsets, not evidence that the sources should
be snapped together. Index-1 comparisons at the same station are invalid because
that track is absent. Nearest-path distances and tangent comparisons will be
reported separately. A connector orientation residual is unavailable without
exported connector orientation; a beam direction is not a connector frame.

Only the local fixture and synthetic examples may supply test coordinates.
No reference implementation code is copied. Imported data stays outside native
project serialization, editing, undo/redo, and vehicle physics.

## Representative XML compatibility references

Read-only schema inspection also covered the author's public
[simple structure example](https://github.com/bestdani/blender_nl2pro_supports/blob/main/example_data/simple%20structure_supports.xml)
and [offsets and prefabs example](https://github.com/bestdani/blender_nl2pro_supports/blob/main/example_data/offsets%20and%20prefabs_supports.xml).
They corroborate the node/beam/fraction representation and demonstrate
`prefab/atomization/supports`: explicit positioned child nodes with global IDs,
including references from later beams. The importer visits this hierarchy without
applying any inferred prefab transform or opening the referenced prefab path.
Nested atomizations are covered by original synthetic tests. A prefab with no
explicit atomization is reported and omitted. Neither public example nor addon
implementation is redistributed; that repository is GPL-3.0. No GPL code was
used in this implementation. Its data was consulted for format facts only.

Pipe type 1 and the footer type labels are additionally corroborated by an
independent library author's [Beam type enumeration](https://github.com/geforcefan/libnolimits/blob/master/libnolimits/NL2/Coaster/Support/Beam.h)
and [Footer type enumeration](https://github.com/geforcefan/libnolimits/blob/master/libnolimits/NL2/Coaster/Support/Footer.h).
These are corroborating references, not an official XML schema. Only round pipe
type 1 is rendered in M1.2; `size1` is its outer diameter. No wall thickness,
structural section properties, or exact NL2 joint solids are inferred. Pipe
rotation and vertical-rotation mode are retained; circular sections are rotationally
symmetric, with a 16-sided visual approximation. The footer basetype 1 denotes
steel round, but its footprint dimensions are absent and are not invented.

## Running the implementation

From the repository root, launch the existing native executable in development
inspection mode:

```powershell
cargo run --release -p quantum-x -- diagnostic-import tests/fixtures/nl2/BROBDINGNAGIAN/BROBDINGNAGIAN.csv tests/fixtures/nl2/BROBDINGNAGIAN/BROBDINGNAGIAN_supports.xml --construction box-spined-100
```

This uses the existing QUANTUM Box-Spined-100 construction and material library;
the exports do not contain the NL2 track family, gauge, exact rail meshes, or
material definitions. The default `--construction generic-dual` uses the existing
provisional validation construction instead. Both preserve the imported sampled
path and frames. Pass `-` instead of the XML path to inspect a track alone. Native
`centerline.csv` (18 columns, commas, including quoted numeric cells) is detected
by its existing header. Native design time is preserved; NL2 has no time field.
No speed or force measurements are synthesized.

For headless evidence, append `--render target/m1.2-brobdingnagian-new` using a
**new** output directory. It writes `overview.png`, `alignment.png`, `detail.png`,
and `report.json` through the existing offscreen renderer. The report includes all
per-connector residuals, typed support counts, bounds, unsupported-feature counts,
materials, mesh statistics, and adapter/upload diagnostics. Local private captures
and per-node reports remain Git-ignored under `target`; they are not uploaded to
the PR or included in packages. The CLI never overwrites an existing output
directory and never writes the source exports.

Developer controls: left-drag orbit, right/middle-drag pan, wheel zoom, F to fit,
Ctrl+R to reload, Escape to close; buttons expose fit and view presets. Visibility
switches show track construction, support beams, exported spline, frames, footer
and connector markers, and connector distance lines. The panel lists actual
material slots and available library materials. These are inspection controls,
not production Track/Support Workspace UX. Reload parses/builds on a worker,
replaces the whole diagnostic scene only on success, and retains the previous
scene on failure. Clear releases diagnostic scene references. It never opens,
serializes, edits or saves a native project.

## Bounded parsing and numerical policy

Limits: 32 MiB per UTF-8 input, 100,000 track samples, 4,096 bytes per numeric row,
20,000 support nodes, 10,000 beams, 150,000 XML DOM nodes, 32 XML levels, 32
attributes per element, and 20 million connector/segment comparisons. Values
must be finite and within a world magnitude of 100 million metres. XML DTDs and
entity declarations are rejected; roxmltree has no external resource resolver.
The existing locked roxmltree 0.20 dependency (MIT OR Apache-2.0) is reused, adding
no new lockfile package. Mesh construction retains the existing mesh budgets.

Sample stations and native time must increase/nondecrease respectively. Ordinals
must be consecutive; duplicate consecutive positions, reversed sample direction,
bad frame handedness, large frame discontinuities and inconsistent native
quaternion/vector pairs fail with row-specific errors. Repeated positions at
nonadjacent samples can represent crossings or loop endpoints and are retained.
NL2 basis tolerance is 5e-5 in norm/dot tests; this fixture's largest axis change
after conversion is 1.39842e-6. No smoothing or resampling is performed. Chord
distance is derived for NL2 because it contains no station column. Neither chord
length nor a nearest-point projection is an exact original NL2 spline query.

Beam nodes interpolate between original node endpoints at their exported
fraction. Positive extra lengths extend the visible pipe along its axis;
negative lengths trim it without moving the connection nodes. IDs must resolve
before a beam, as specified by NL2; duplicates and dangling IDs fail. Unknown
properties are counted and original XML is retained in diagnostic memory. Unknown
structural containers are omitted as subtrees, avoiding unverified transformations.

track uses existing QUANTUM material slots (eight library materials are listed).

physics inputs, ground extensions, or additional supports are generated.

For other exports, nonpipe beam profiles, unresolved prefabs, explicit beam offset
properties, custom connector shapes, LOD/cap/color options and unknown tags are
reported as unsupported. They are not claimed as full NL2 compatibility.

## Future terrain integration

Use a separately licensed heightfield or mesh plus explicit metres, axis, origin,
resolution and elevation datum metadata. Preserve the current world coordinates;
keep view-relative GPU origins separate from document geometry. Add terrain as a
separate read-only layer first, with independent visibility and bounds. Compare
footer elevations against that measured surface and report gaps before proposing
any reversible editing command. Do not derive terrain from footer positions or
use `height_above_terrain` as a complete foundation specification. A second track
export with an explicit track-index mapping is needed for the five branch
connectors; terrain importing cannot recover that missing track.

## UX and manual acceptance

Owner-approved behavior implemented: separate CLI diagnostic launch, read-only
track/support inspection, existing construction/material display, navigation and
fit. The new panel is explicitly temporary developer UI. No production workspace,
authoring workflow, document schema, undo/redo, transition evaluation, generation
semantics or rigid-body simulation was changed. Production import UX and exact
NL2 connector/foundation presentation still require human design/source evidence.

Native GUI interaction is **not manually verified**. No desktop control was used.
On the owner's Windows machine, run the launch command, orbit/pan/zoom, press F,
toggle each geometry layer, inspect the close-up connections and footer markers,
reload with Ctrl+R, clear, then reload again. Confirm failure on an unavailable
source retains the previous scene. Native project editing/save/reopen should
remain available through the ordinary executable launch, separately from this
diagnostic window. Automated headless checks are recorded below.
