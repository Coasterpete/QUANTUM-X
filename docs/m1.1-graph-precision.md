## Implemented behavior

Draft curves, dashed committed overlays and Fit Curve now use a common read-only
scalar-profile plotting utility. Nonzero native knot spans are considered before
adaptive refinement. A narrow span is not discarded because it is subpixel in X,
and agreement at endpoints/midpoint is not used as a flatness proof.

- [`qx-geometry/profile_plot.rs`](../crates/qx-geometry/src/profile_plot.rs)
  computes positive-weight homogeneous Bernstein nets for each clipped knot span.
  This is a temporary plotting basis; the authored NURBS is neither rewritten nor
  converted to a different saved representation. Repeated knots delimit spans;
  zero-width knot intervals are skipped.
- For a rational scalar `y=N/W`, the vertical chord-error calculation bounds
  `N-LW` in degree `p+1` Bernstein form, divided by positive elevated denominator
  coefficients. Rational control abscissae cannot be treated as uniformly spaced
  points on the graph. Subdivision uses de Casteljau in homogeneous coordinates.
- Polynomial legacy functions use a temporary exact plotting basis. Cosine and
  legacy cosine spans retain an analytic cosine term, bounded by endpoint/phase
  extrema and a second-derivative interpolation estimate; no finite NURBS
  approximation is substituted for cosine evaluation.
- [`graph_curve.rs`](../apps/quantum-x/src/authoring/graph_curve.rs) converts half
  a logical pixel to output-unit tolerance and supplies the same sampling path to
  both styles. Committed curves are dashed in screen space after sampling, so
  alternating parameter intervals are no longer discarded before evaluation.
- [`View::fit`](../apps/quantum-x/src/authoring/graph_view.rs) uses tightened
  conservative extrema enclosures with the existing 15% margin and existing
  constant-profile unit margins. Fit bounds are independent of the current view.
  Automatic first-visit fitting benefits from the same correction.
- When detail cannot be resolved, the renderer outlines the enclosing interval
  and uses the existing reserved graph readout to explain the limit. It does not
  advertise a coarse chord as accurate. No new mode, button or editing gesture
  was introduced.

`Transition::evaluate`, `NurbsProfile::evaluate`, profile validation, integration,
continuity, document formats, Region boundaries, commands and undo/redo code were
not changed. Sample endpoints still come from the existing validated evaluator.
Drawing and fitting only borrow authored state. Mathematical evaluation and
visual approximation remain distinct.

## Budgets and numerical limits

A transition has at most 256 controls, degree 3–5, and at most 253 nonzero spans.
Visible plotting permits up to 2,048 output segments per transition, with a shared
16,384-segment detail allowance across draft/committed drawing in a graph frame.
After that allowance, at most one enclosing segment is emitted per remaining
nonempty transition. With two valid 4,096-transition channels the output cap is
therefore at most 24,576 segments. Preparing/validating each visible transition
still has a cost; this is not a measured frame-rate guarantee. Dashing and stroke
tessellation have additional screen-dependent costs.

The geometry API rejects zero/excessive budgets and invalid tolerance/ranges. If
there is not enough budget even for all mandatory spans, their hulls are combined
into one explicit unresolved enclosure. Refinement splits only when its output
and pending leaves fit the budget; depth is at most 48 and subdivision stops at
unresolvable `f64` coordinates. A depth-first traversal can leave later intervals
coarser when an earlier interval uses its allowance. None of those intervals is
silently omitted.

Fit uses at most 2,048 leaves per transition, with target tightening tolerance
`max(initial_range*1e-7, magnitude*1024*EPSILON, 1e-12)`. It retains the remaining
control hull if that target cannot be met. Fit can be loose on adversarial rational
weights or large/oscillatory cosine spans. Exact extrema/root guarantees are not
claimed for all profiles. Positive-weight hulls are conservative in real
arithmetic; floating-point calculations have magnitude-scaled roundoff guards,
but this is **not directed-rounding interval arithmetic or a formal numerical
certificate**. Existing knot snapping and representable-coordinate/evaluator
limits remain unchanged. A feature narrower than a pixel can show as a vertical
trace until zoomed; drawing does not invent a finite visible width for it.

No sampling cache was introduced. Profiling-driven caching is an optional later
optimization requiring revision/view invalidation tests.

## Reproduced failure and regression results

Fixture: cubic, 11 controls, positive unit weights, simple internal knots at
`0.5, 0.5001, ..., 0.5006`; only control 5 has value 1. Both interior and boundary
constraints permit the intended C2 profile. It is synthetic numerical test data,
not an owner-authored coaster or a suggested ride shape.

| Measurement | Observed result |
| --- | --- |
| Existing evaluator at `x=0.5003` | `0.6666666666666667` |
| Old 129-point full-domain display maximum | `0` |
| Old 513-point Fit Curve sample maximum | `0` |
| New sampler maximum, tolerance `0.001` | `0.6666666666666667` |
| New output at that tolerance | 62 segments; no unresolved intervals |
| Extrema enclosure | `[-1.8947806286936007e-14, 0.6666666666667426]` |
| Fitted Y bounds with existing margin | `[-0.10000000000003317, 0.7666666666667568]` |

The focused geometry tests compare each resolved chord with the existing evaluator
at 33 points per output interval and test enclosing ranges as well as peaks.
Other cases cover endpoint pulses, widths down to `1e-10`, repeated/nonuniform
knots, clipped spans, rational weights, degree 3/4/5, legacy polynomial and cosine
profiles, a cubic with equal endpoint/midpoint values but nonzero lobes, constants,
empty intervals, malformed data, and forced budget exhaustion.

The 256-control adversarial test uses weights alternating `1e-8`/`1e8`, a 256-leaf
budget and an unattainably strict plotting tolerance; it returns exactly 256
segments, reports unresolved detail and retains finite fit bounds. Its debug
timing is informational in the focused-test log, with no flaky wall-time limit.
Operation counts/leaf caps, not a claimed FPS result, verify bounded cost.

Editor regressions check both solid/dashed GPU input geometry, existing fit
constant margins, zoom/pan clipping, explicit budget feedback and preservation of
document/draft/history. Apply, undo, redo and serialization remain exercised.
The preexisting integration fixture and full numerical regression suite remain
part of workspace verification.

The saved checkpoint executable and final Release executable also generated the
same persisted fixture separately. SHA-256 comparison found **10 byte-identical
numeric/persistence artifacts**, including centerline/measurements/transitions
